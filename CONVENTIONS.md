# Conventions (agents-base-v1)

The base is split into four layers, each living in the primitive that fits so responsibilities stay separate and any drift shows up in diffs: **reference knowledge → a skill** (`skills/agent-roster-reference/`, injected into meta-agents via the `skills:` preload field); **deterministic operations → scripts + commands** (`scripts/*.sh` driven by `commands/*.md` — no model in the loop for a rename, a listing, a lock, or tune-loop bookkeeping); **post-edit validation → a hook** (`scripts/validate-frontmatter.py`, wired as a PostToolUse `Edit|Write|MultiEdit` hook through `$CLAUDE_PROJECT_DIR`, which re-parses frontmatter and exits 2 on a missing/empty `name`, a missing/placeholder `description`, or a `name` duplicated across the tree); and **judgment → a slim subagent** (`agents/agent-manager.md`). Frontmatter and invocation rules: identity is the frontmatter `name` (never the filename or folder — keep it unique across the whole tree); encode invocation policy in frontmatter, never as prose inside `description` (the description is the router's match text), using `disable-model-invocation: true` for explicit-only agents and scoped `agents:` allowlists on coordinators so routing stays two-level as the roster grows past a few dozen; commands reach scripts as `$CLAUDE_PROJECT_DIR/scripts/<x>.sh` and declare `allowed-tools` (project-vendored install via `scripts/install.sh`, restart required for discovery); and every destructive op goes through `mv` (the `locked_` prefix or a `.md.off` suffix), never `rm`, with each git commit scoped to the single file edited.
